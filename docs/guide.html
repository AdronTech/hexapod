1. The Robot

Physical layout, leg naming, and body geometry

A hexapod is a six-legged robot. Each leg has three joints — 18 servo motors total. Understanding the naming is the foundation for everything.

Three Joints per Leg

Click a joint name below to highlight it on the diagram.

Coxa (joint 1)

The "hip". Rotates the leg horizontally (yaw). ID = leg×10+1

Femur (joint 2)

The "thigh". Rotates up/down (pitch). Controls height. ID = leg×10+2

Tibia (joint 3)

The "shin". Controls reach. ID = leg×10+3

Servo ID Scheme

servo_id = leg_index × 10 + joint_index Leg 1 Coxa → 11   Leg 2 Femur → 22   Leg 5 Tibia → 53

2. Servos & Protocol

ST3020 servos, tick encoding, and the SCS bus protocol

What Is a Tick?

Each servo reports its angle as an integer 0–4095 called a tick. The encoder has 4096 positions per full revolution. Tick 2048 = 0° (neutral). Drag the slider.

Tick: 2048
Degrees: 0.0°
Radians: 0.000
degrees = (tick − 2048) × 0.08789° tick = 2048 + round(degrees / 0.08789)

Sign Conventions per Joint

Each joint has a different sign so the IK angles stay physically intuitive (positive = naturally upward/outward direction).

JointPositive angle meansTick formula
CoxaCCW from above (forward sweep for right-side legs)tick = 2048 − round(θ/0.08789)
FemurTip rises above horizontaltick = 2048 − round(θ/0.08789)
TibiaTip swings outward/downtick = 2048 + round(θ/0.08789)
The tibia sign is opposite to coxa and femur. Always use angle_to_tick(joint, degrees).

The SCS Bus Protocol

All 18 servos share one serial wire (half-duplex). You address each by ID. The critical operation is sync write: one broadcast packet that moves all 18 simultaneously.

Packet Format

TX: FF FF ID LEN INSTR [PARAMS...] CHECKSUM RX: FF FF ID LEN ERROR [DATA...] CHECKSUM CHECKSUM = ~(ID + LEN + INSTR + sum(PARAMS)) & 0xFF LEN = len(PARAMS) + 2

3. Coordinate Frames

How positions are expressed in different reference frames

World Frame

Fixed to the ground. Feet on ground → z=0. Used for gait planning.

Body Frame

Fixed to the chassis. Origin at body center. X=forward, Y=left, Z=up.

Leg Frame

Origin at each coxa pivot. X=radially outward. One per leg. Used for single-leg IK.

Drag the sliders to move and rotate the body relative to the world frame.

Top-down view — world/body/leg frames

Body → Leg Transform

To get foot position in leg frame from body frame: 1. Subtract corner position: foot_rel = foot_body − corner_pos(leg) 2. Rotate by −corner_angle: leg_x = foot_rel.x·cos(α) + foot_rel.y·sin(α) leg_y = −foot_rel.x·sin(α) + foot_rel.y·cos(α) leg_z = foot_rel.z where α = corner angle (e.g. −30° for FR leg)

5. Inverse Kinematics

Given foot position → what joint angles?

IK solves analytically (no iteration). Click or drag on the canvas to move the foot target. Blue = reachable, red = out of range.

Click or drag to set foot target
Angles: coxa 0.0° | femur 0.0° | tibia 0.0°
Ticks: 11→2048 12→2048 13→2048
  1. Coxa yaw: θc = atan2(y, x)
  2. Project to vertical plane: rh = hypot(x,y) − COXA  |  d = hypot(rh, z)
  3. Check reachability: |FEMUR−TIBIA| ≤ d ≤ FEMUR+TIBIA
  4. Elevation angle + law of cosines: φ = atan2(z, rh)  |  β = acos((F²+d²−T²)/(2Fd))
  5. Femur (elbow-down): θf = φ + β
  6. Tibia relative to femur: tibia_abs = atan2(z − F·sin θf, rh − F·cos θf)  →  θt = tibia_abs − θf + 90°

6. Body IK

Moving the whole body in 6 degrees of freedom

Body IK keeps all feet planted on the ground while the body tilts/translates. Drag sliders to pose the body and see how each leg adapts.

Oblique 3D projection — left=front view, right=top view
Hover over a leg to see its angles

Two-Layer Architecture

body_ik(feet_body) — feet in body frame → call single-leg IK for all 6 legs

body_pose_ik(pose, feet_world) — rotate/translate feet from world frame into body frame, then call body_ik

foot_body = R_inv × (foot_world − body_translation) R = Rz(yaw)·Ry(pitch)·Rx(roll) (ZYX convention)

7. Gaits

Coordinated leg movement patterns

A gait assigns each leg a phase offset. When a leg's clock enters its swing window it lifts off; otherwise it's on the ground pushing the body.

Timing chart — green=stance, orange=swing | click chart to scrub
Tripod: 2 groups of 3 | 50% swing | ≥3 legs always grounded

Tripod

Groups: {1,3,5} and {2,4,6} alternate. Fastest. Exactly 3 on ground.

Duty 50% stance

Ripple

Three groups of 2, staggered. 4 legs grounded. Medium speed.

Duty 67% stance

Wave

Each leg steps alone. Always 5 grounded. Slowest, most stable.

Duty 83% stance

Turntable — Predictive Foot Placement

When a leg steps, it must land such that the foot is at neutral mid-swing. So it lands half a stride ahead:

landing = neutral + velocity × stance_duration × 0.5 + rotate(neutral, omega × stance_duration × 0.5)

9. Free Gait

Reactive stepping based on foot drift

No fixed schedule. Each leg steps when its foot drifts too far from neutral. The robot decides independently, but must not tip over.

drift = |foot_pos − neutral_pos| if drift > threshold → schedule step (land at neutral)

Stability Guard: at most 3 non-adjacent legs swinging

Top-down view | green=grounded, orange=swinging | numbers=drift cm
  1. Collect grounded legs where drift > threshold, sort by drift (highest first)
  2. For each: skip if adjacent leg is already swinging
  3. Skip if ≥3 legs already swinging
  4. Emergency: if drift > 2×threshold, allow even with adjacent leg swinging
  5. Land at neutral foot position (clamped to reach limits)

10. The Control Loop

20 Hz real-time execution on a background thread

State Machine

ButtonModeWhat happens
AStandIK for neutral pose at 15 cm, MotionPlayer smoothly moves all 18
BSitAll servos → 2048, torque off
XWalkCycle gait types; left stick=direction, right stick=turn
BackFreeFreeGait + full body control
YStoreFold legs, torque off

Gamepad Axes

Left stick X/Y → vy, vx (side/forward velocity cm/s) Right stick X → omega (rotation rate °/s) LT / RT → height (body Z ±) LB / RB → reach (stride size ±)

Deadzone Processing

if |v| < 0.12: return 0 else: return sign(v) × (|v| − 0.12) / (1 − 0.12)

20 Hz Timing

DT = 0.05  # 50 ms target
t0 = time.monotonic()
# ... IK + 18 servo writes ...
elapsed = time.monotonic() - t0
time.sleep(max(0, DT - elapsed))

11. The Full Pipeline

Gamepad input → servo tick, every 50 ms

Build Order (from scratch)

  1. Serial transport + SCS packet builder/parser
  2. Servo register map + ping/read/write/sync_write
  3. Single-leg FK and IK + tick conversion
  4. Body geometry (corner angles) + body/pose IK
  5. Tripod gait with Bézier swing + turntable foot placement
  6. Soft limits from JSON, checked before every write
  7. SharedState + control thread + stand/sit/walk state machine
  8. Web UI with Gamepad API + WebSocket + config sliders
Key insight: Everything except the gait engine is a pure function per frame — IK, frame transforms, tick conversion. Only the gait accumulates state over time. This makes each layer independently testable.
